Performance

QAOA.jl does not build a quantum circuit. It applies each layer of the QAOA to the state vector directly, with loops written for the two parts of a layer. On this page, we explain these loops and give timings, so that you can estimate how large a problem your computer can handle.

All three packages agree on the expectation values to 13 digits. QAOA.jl 1.4 allocated 3.6 GB per evaluation at 20 qubits; QAOA.jl 2.0 allocates nothing. With four threads, 20 qubits take 1.7 ms and 24 qubits 35 ms, halved by symmetry. The expectation value and its derivatives with respect to all angles cost about three times one expectation value: for 14 qubits and 10 layers, 3.5 ms, against 14 ms for JuliQAOA and 84 ms for QAOA.jl 1.4.

The Two Parts of a Layer

The phase separator multiplies every amplitude by a phase that depends only on the objective of its assignment. The Workspace computes these objectives once, for all 2^n assignments. For an Ising or QUBO problem, adding a variable doubles the table of objectives, so the whole table costs O(2^n) operations; for 20 qubits, less than a millisecond. When all weights are integers, or multiples of 1/16, the objective takes at most 65535 values, and the workspace stores a two-byte index into a table of these values instead of an eight-byte number. The phase separator then computes one complex exponential per distinct value instead of one per assignment.

The mixer turns each qubit separately. The amplitudes are read and written once per pass over the state vector, and for a large state, memory traffic sets the time. The workspace therefore turns the eleven lowest qubits block by block, inside 32 KiB of the state at a time, together with the phase separator. The remaining qubits are turned two per pass.

Halving by Symmetry

Many objectives do not change when all variables flip at once: MaxCut, the Sherrington–Kirkpatrick model and number partitioning, for example. Then the two amplitudes of an assignment and of its complement stay equal throughout the QAOA, and the workspace stores only one of them. This halves memory and time and changes no result. A workspace detects the symmetry by itself; symmetry = false turns it off. It needs the X mixer and the default initial state.

Gradients

expectation_and_gradient computes the derivatives of the expectation value with respect to all 2p angles by the adjoint method: after the forward run, it goes back through the layers once, undoing them on the state and on a second vector. This costs about two more runs, for any number of layers, and one more state vector of memory.

Threads

The passes over the state vector split over Julia's threads when the state has at least 2^15 amplitudes. Start Julia with several threads, for example julia --threads=auto. Smaller states run on one thread: for them, starting threads costs more than it saves. To use all cores for many small problems, run one problem per thread instead.

Memory and the Largest Problems

Every stored assignment takes 16 bytes for its amplitude and 8 bytes for its objective, or 2 bytes with integer weights. A gradient needs another 16 bytes per assignment. Halving by symmetry halves all of this.

A computer with 24 GB of memory thus handles about 29 qubits, or 30 halved by symmetry. One layer with 28 qubits takes 1.4 s on four cores of an Apple M4, or 0.7 s halved by symmetry.
