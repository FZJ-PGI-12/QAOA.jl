QAOA.jl

QAOA.jl is a lightweight and efficient implementation of the Quantum Approximate Optimization Algorithm (QAOA), built to support the extensive classical simulations typically required in research on the topic. QAOA.jl keeps the quantum state of all qubits in memory and thus gives exact probabilities and expectation values, together with their gradients with respect to the angles of the algorithm. One expectation value for 20 qubits takes a few milliseconds, and 30 qubits fit into the memory of a laptop. A number of common optimization problems such as MaxCut, the minimum vertex-cover problem, the Sherrington-Kirkpatrick model, and the partition problem are pre-implemented to facilitate scientific benchmarking.

The mean-field AOA has moved to MFAOA.jl

Up to version 1.4, QAOA.jl also implemented the Mean-Field Approximate Optimization Algorithm (mean-field AOA). That algorithm now has its own package, MFAOA.jl. Both packages describe a problem and its angles in the same way, so we can run the QAOA with QAOA.jl and its mean-field approximation with MFAOA.jl in the same script. Note that the two packages export many of the same names; load the second one with import MFAOA and write MFAOA.solve and so on. The Gaussian fluctuation analysis of the mean-field AOA (evolve_fluctuations) is available in QAOA.jl 1.4 and earlier.

Installation

To install, use Julia's built-in package manager

A First Example

The MaxCut problem splits the nodes of a graph into two groups such that as many edges as possible join nodes of different groups. A ring of five nodes has five edges, and at most four of them can be cut. We can solve this problem with QAOA.jl as follows:

using QAOA, Random
ring = max_cut(5, [(1, 2), (2, 3), (3, 4), (4, 5), (5, 1)])
result = solve(ring; p = 20, rng = Xoshiro(1))
Result{Float64}: 5 variables, objective = 4.0, expectation = 3.9976427862569546

solve runs the QAOA with 20 layers, measures the final quantum state 1000 times and returns the best bitstring it saw. Its objective is the number of edges cut, and the bits x give the group of each node:

result.objective, result.x
(4.0, Int8[1, 0, 1, 0, 0])

The expectation value, i.e. the average cut over all measurements, comes close to the maximum:

result.expectation
3.9976427862569546

The Algorithm

For a problem with $n$ binary variables, the QAOA uses $n$ qubits. When we measure them, qubit $i$ in the state $|1\rangle$ means $x_i = 1$, or the spin $\sigma_i = +1$ in an Ising problem. The QAOA prepares the state

\[\begin{align*} |\beta, \gamma\rangle = e^{-i \beta_p \hat B} e^{-i \gamma_p \hat C / s} \cdots e^{-i \beta_1 \hat B} e^{-i \gamma_1 \hat C / s} |+\rangle^{\otimes n}, \end{align*}\]

where $\hat C$ is the cost function as an operator, $\hat C |x\rangle = C(x) |x\rangle$, and $\hat B = \sum_i \hat X_i$ is the mixer. The state $|+\rangle^{\otimes n}$ gives all $2^n$ bitstrings the same amplitude. Each of the $p$ layers then does two things:

  1. The phase separator $e^{-i \gamma_k \hat C / s}$ multiplies the amplitude of every bitstring by a phase that depends on its cost function. For a minimization, the phase has the opposite sign.
  2. The mixer $e^{-i \beta_k \hat B}$ turns every qubit, which moves amplitude between bitstrings that differ in one bit.

The angles $\beta_k$ and $\gamma_k$ form a Schedule. With good angles, the bitstrings with good cost functions end up with large amplitudes, so a measurement is likely to return one of them.

The scale $s$ is the fieldscale of the problem. Since we measure $\gamma$ in units of $s$, good angles do not depend on the units of the cost function or on the size of the problem. With many layers and slowly changing angles, the QAOA becomes a quantum annealing from the mixer to the cost function, and linear_schedule builds such a schedule. With few layers, optimized angles do better; optimize_schedule finds them.

Problems

QAOA.jl describes a problem by one of three types:

  • IsingProblem has spins $\sigma_i = \pm 1$ and the cost function $C(\sigma) = \sum_i h_i \sigma_i + \sum_{i<j} J_{ij} \sigma_i \sigma_j + \mathrm{offset}$.
  • QUBOProblem has bits $x_i \in \{0, 1\}$ and the cost function $C(x) = \sum_{i,j} Q_{ij} x_i x_j + \sum_i c_i x_i + \mathrm{constant}$.
  • GeneralProblem takes any cost function, as a function of the bits or as a table of its values.

Each problem is minimized by default; sense = :max maximizes it. The wrapper functions max_cut, min_vertex_cover, sherrington_kirkpatrick and partition_problem set up common problems. With Graphs.jl loaded, max_cut and min_vertex_cover also take a graph.

Workspaces

A Workspace holds everything the QAOA needs for one problem: the cost function of every bitstring and the quantum state. expectation, probabilities, statevector, expectation_and_gradient and solve take a workspace or a problem. Given a problem, they build a workspace first. When we evaluate many schedules for the same problem, as in an optimization of the angles, we should reuse one workspace:

ws = Workspace(ring)
tuned, value = optimize_schedule(ws, 3)
value
4.0

Our page on performance explains how the workspace saves time and memory, and how to use several threads.

Problems

QAOA.IsingProblem — Type
IsingProblem(h, J; Δ = nothing, offset = 0, sense = :min, scale = nothing)

An optimization problem over spins $\sigma_i = \pm 1$.

Input

  • h::AbstractVector: The local fields $h_i$.
  • J::AbstractMatrix: The couplings $J_{ij}$, symmetric with a zero diagonal. J can be dense or sparse.
  • Δ (optional): One positive factor per spin on the mixer angles $\beta$. The default, nothing, means 1 for every spin.
  • offset::Real=0 (optional): A constant added to the cost function.
  • sense::Symbol=:min (optional): :min to minimize the cost function, :max to maximize it.
  • scale (optional): The unit of the angles $\gamma$, see fieldscale. The default makes the algorithm independent of the units of h and J; scale = 1 uses those units themselves.

Output

  • An IsingProblem holding all relevant quantities.

Notes

The cost function is

\[C(\sigma) = \sum_{i=1}^N h_i \sigma_i + \sum_{i<j\leq N} J_{ij} \sigma_i \sigma_j + \mathrm{offset}.\]

Since $\sigma_i^2 = 1$, a diagonal entry of J would only add a constant; put it into offset instead. When the QAOA is measured, qubit $i$ in the state $|1\rangle$ means $\sigma_i = +1$, and $|0\rangle$ means $\sigma_i = -1$.

The arguments mean the same as in MFAOA.jl, which runs the mean-field approximation of the same algorithm: a problem and a Schedule written for one package work in the other.

source
QAOA.QUBOProblem — Type
QUBOProblem(Q; c = zeros(n), constant = 0, sense = :min)

An optimization problem over bits $x_i \in \{0, 1\}$.

Input

  • Q::AbstractMatrix: The quadratic weights $Q_{ij}$, used exactly as given: a symmetric matrix counts each pair of bits twice, an upper-triangular matrix once.
  • c::AbstractVector=zeros(n) (optional): The linear weights $c_i$.
  • constant::Real=0 (optional): A constant added to the cost function.
  • sense::Symbol=:min (optional): :min to minimize the cost function, :max to maximize it.

Output

  • A QUBOProblem holding all relevant quantities.

Notes

The cost function is

\[C(x) = \sum_{i,j=1}^N Q_{ij} x_i x_j + \sum_{i=1}^N c_i x_i + \mathrm{constant}.\]

Diagonal entries of Q act as linear weights, since $x_i^2 = x_i$. When the QAOA is measured, qubit $i$ in the state $|1\rangle$ means $x_i = 1$. The angles $\gamma$ are measured in units of the fieldscale of the same problem in Ising form, IsingProblem(prob).

source
QAOA.GeneralProblem — Type
GeneralProblem(values; sense = :min, scale = nothing)
GeneralProblem(f, n; sense = :min, scale = nothing)

An optimization problem given by the cost function of every bitstring, for cost functions that are not quadratic, such as those of satisfiability problems.

Input

  • values::AbstractVector: The cost function of every bitstring of $n$ bits, so values has length $2^n$. values[b + 1] belongs to the bitstring whose bit $x_i$ is bit i - 1 of the integer b.
  • f, n::Integer: Alternatively, a function f(x) returning the cost function of the bitstring x, a Vector{Int8} of n ≤ 30 zeros and ones. Note that f must not keep x, which is reused.
  • sense::Symbol=:min (optional): :min to minimize the cost function, :max to maximize it.
  • scale (optional): The unit of the angles $\gamma$, see fieldscale.

Output

  • A GeneralProblem holding all relevant quantities.

Notes

By default, scale is the root mean square, over all bitstrings and bits, of half the change of the cost function when one bit flips. For a quadratic cost function, this equals the fieldscale of the problem in Ising form.

QAOA.fieldscale — Function
fieldscale(prob) -> s

Returns the unit $s$ in which a Schedule measures the angles $\gamma$ for prob.

Notes

In layer $k$, the QAOA multiplies the amplitude of every bitstring by the phase $e^{-i\gamma_k C / s}$, where $C$ is the cost function of that bitstring (with the opposite sign for a minimization). Unless scale was given when the problem was built, $s$ is the root mean square of the local field $m_i = h_i + \sum_j J_{ij} \sigma_j$ over all spins $i$ and random spins $\sigma$,

\[s = \sqrt{\frac{1}{N} \Big(\sum_{i=1}^N h_i^2 + \sum_{i,j=1}^N J_{ij}^2\Big)}.\]

Multiplying the cost function by a constant multiplies $s$ by the same constant, so the same angles suit problems in any units.

Predefined Optimization Problems

QAOA.max_cut — Function
max_cut(n, edges; weights = nothing) -> IsingProblem

Wrapper function setting up an instance of the MaxCut problem for a graph with the nodes 1:n.

Input

  • n::Integer: The number of nodes.
  • edges: The edges of the graph, as pairs of nodes (i, j).
  • weights (optional): One weight $w_{ij}$ per edge, 1 by default.

Output

  • An IsingProblem to be maximized.

Notes

Spin $\sigma_i = \pm 1$ says which of the two groups node $i$ joins, and the cost function is the weight of the cut,

\[C(\sigma) = \sum_{(i, j) \in E(G)} w_{ij} \frac{1 - \sigma_i \sigma_j}{2},\]

where $E(G)$ is the set of edges of the graph $G$. With Graphs.jl loaded, max_cut(g) takes a graph g instead.

source

Wrapper function setting up an instance of the MaxCut problem for the graph g from Graphs.jl, with the edge weights of g (1 for an unweighted graph). See max_cut.

QAOA.min_vertex_cover — Function
min_vertex_cover(n, edges; penalty = 2) -> QUBOProblem

Wrapper function setting up an instance of the minimum vertex cover problem for a graph with the nodes 1:n.

Input

  • n::Integer: The number of nodes.
  • edges: The edges of the graph, as pairs of nodes (i, j).
  • penalty::Real=2 (optional): The penalty $P > 1$ for each edge without a chosen end.

Output

  • A QUBOProblem to be minimized.

Notes

Bit $x_i = 1$ means that node $i$ is chosen. The cost function

\[C(x) = \sum_{i \in V(G)} x_i + P \sum_{(i, j) \in E(G)} (1 - x_i)(1 - x_j)\]

counts the chosen nodes plus $P$ for each edge without a chosen end, where $V(G)$ is the set of vertices and $E(G)$ is the set of edges of the graph $G$. With $P > 1$, every minimum is a cover: adding a node to cover an edge costs 1 and saves at least $P$. With Graphs.jl loaded, min_vertex_cover(g) takes a graph g instead.

QAOA.sherrington_kirkpatrick — Function
sherrington_kirkpatrick(n; seed = 1) -> IsingProblem

Wrapper function setting up an instance of the Sherrington-Kirkpatrick model.

Input

  • n::Integer: The number of spins.
  • seed::Integer=1 (optional): The seed for the random-number generator Xoshiro used for the couplings.

Output

  • An IsingProblem to be minimized.

Notes

The cost function is

\[C(\sigma) = \frac{1}{\sqrt{n}} \sum_{i<j\leq n} J_{ij} \sigma_i \sigma_j,\]

where the couplings $J_{ij}$ are i.i.d. standard Gaussian variables. The problem stores $J_{ij}/\sqrt{n}$ as its couplings.

QAOA.partition_problem — Function
partition_problem(a) -> IsingProblem

Wrapper function setting up an instance of the partition problem.

Input

  • a::AbstractVector{<:Real}: The numbers to be partitioned.

Output

  • An IsingProblem to be minimized.

Notes

The partition problem for a set of numbers $\mathcal{S} = \{a_1, ..., a_N\}$ consists of finding two subsets $\mathcal{S}_{1} \cup \mathcal{S}_2 = \mathcal{S}$ such that the difference of the sums over the two subsets is as small as possible. Spin $\sigma_i = \pm 1$ says which subset $a_i$ joins, and the cost function is the squared difference

\[C(\sigma) = \Big(\sum_{i=1}^{N} a_i \sigma_i\Big)^2 = \sum_{i<j\leq N} J_{ij} \sigma_i \sigma_j + \sum_{i=1}^N a_i^2\]

with $J_{ij} = 2 a_i a_j$.

Schedules

QAOA.Schedule — Type
Schedule(β, γ)

A container holding the angles of a QAOA with $p$ layers, one pair $\beta_k$, $\gamma_k$ per layer $k$.

Input

  • β::AbstractVector: The angles of the mixer.
  • γ::AbstractVector: The angles of the phase separator, in units of the fieldscale of the problem.

Both vectors must have the same length $p$.

Notes

The QAOA starts with every qubit in the state $|+\rangle$, which gives every bitstring the same amplitude. Each layer $k$ then does two things:

  1. It multiplies the amplitude of every bitstring by the phase $e^{-i\gamma_k C / s}$, where $C$ is the cost function of that bitstring and $s$ the fieldscale of the problem. For a minimization, the phase is $e^{+i\gamma_k C / s}$.
  2. It applies the mixer with angle $\beta_k$. The default mixer turns every qubit $i$ by $e^{-i\beta_k \Delta_i X_i}$, where $\Delta_i$ is 1 unless the problem sets it.

linear_schedule builds the usual starting point, and optimize_schedule tunes the angles.

source
QAOA.linear_schedule — Function
linear_schedule(p, τ = 0.5; T = Float64)

Returns a linear annealing schedule with p layers, the usual starting point of the QAOA.

Input

  • p::Integer: The number of layers.
  • τ::Real=0.5 (optional): The length of one annealing step.
  • T=Float64 (optional): The floating-point type of the angles.

Output

  • A Schedule with the angles

\[\gamma_k = \tau \frac{k}{p}, \qquad \beta_k = \tau \Big(1 - \frac{k - 1}{p}\Big), \qquad k = 1, \dots, p.\]

Notes

This is a quantum annealing from the mixer to the cost function, cut into $p$ steps of length $\tau$, and the same schedule as in MFAOA.jl. Since $\gamma$ is measured in units of the fieldscale of the problem, the same $\tau$ suits problems of any size and units. With more layers, the angles change more slowly from one layer to the next, which usually gives better solutions.

source
QAOA.interpolate_schedule — Function
interpolate_schedule(sched) -> Schedule

Returns a schedule with one more layer, interpolated linearly from sched.

Notes

Good angles for $p$ layers, interpolated this way, are good starting angles for $p + 1$ layers. This is the INTERP strategy of Zhou et al., Phys. Rev. X 10, 021067 (2020). With $\theta$ standing for $\beta$ or $\gamma$,

\[\theta'_k = \frac{k - 1}{p} \theta_{k-1} + \frac{p - k + 1}{p} \theta_k, \qquad k = 1, \dots, p + 1,\]

where $\theta_0 = \theta_{p+1} = 0$.

QAOA.optimize_schedule — Function
optimize_schedule(ws, sched; maxiter = 500, gtol = 1e-6) -> (Schedule, Float64)
optimize_schedule(prob, sched; maxiter, gtol, kwargs...) -> (Schedule, Float64)

Optimizes the angles of the QAOA, starting from sched.

Input

  • ws::Workspace: The workspace of the problem. Given a problem prob instead, a Workspace is built first, with the keywords kwargs.
  • sched::Schedule: The initial angles.
  • maxiter::Integer=500 (optional): The maximum number of optimization steps.
  • gtol::Real=1e-6 (optional): The optimization stops when no derivative exceeds gtol in units of the fieldscale.

Output

  • The optimized Schedule.
  • The expectation value of the cost function for these angles.

Notes

The search is a local one: the BFGS method with exact derivatives from expectation_and_gradient!. It minimizes the expectation value for sense = :min and maximizes it for sense = :max.

source
optimize_schedule(ws, p::Integer; τ = 0.5, maxiter = 500, gtol = 1e-6) -> (Schedule, Float64)
optimize_schedule(prob, p::Integer; τ, maxiter, gtol, kwargs...) -> (Schedule, Float64)

Optimizes the angles of p layers, one layer at a time.

Input

  • ws::Workspace: The workspace of the problem. Given a problem prob instead, a Workspace is built first, with the keywords kwargs.
  • p::Integer: The number of layers.
  • τ::Real=0.5 (optional): The step length of linear_schedule(1, τ), the starting point for the first layer.
  • maxiter, gtol (optional): As for a given initial schedule, see above.

Output

  • The optimized Schedule.
  • The expectation value of the cost function for these angles.

Notes

First, one layer is optimized, starting from linear_schedule(1, τ). Each further layer then starts from the interpolate_schedule of the previous optimum. Good angles usually change smoothly with the number of layers, so each search starts close to its optimum.

Running the QAOA

QAOA.Workspace — Type
Workspace(prob; mixer = XMixer(), initial_state = nothing, symmetry = true,
          threaded = Threads.nthreads() > 1)

A container holding everything a QAOA run on prob needs, computed or allocated once: the cost function of every bitstring and the state vector. Reuse a workspace for many schedules of the same problem, as an optimization of the angles does.

Input

  • prob: The problem.
  • mixer (optional): XMixer() or an XYMixer.
  • initial_state (optional): A vector of $2^n$ amplitudes. By default, every qubit starts in the state $|+\rangle$.
  • symmetry::Bool=true (optional): Whether to store only half of the state if the cost function allows it, see below.
  • threaded::Bool (optional): Whether to split the work on states of $2^{15}$ amplitudes or more over Julia's threads. Start Julia with --threads to use it.

Notes

  • If the cost function does not change when all variables flip, as for an IsingProblem without local fields such as MaxCut, the QAOA state has the same symmetry. The workspace then stores only half of it, which halves memory and time without changing any result. This needs the X mixer and the default initial state.
  • The cost function of every bitstring takes 8 bytes, or 2 for cost functions with integer weights, and the state 16 bytes. A gradient needs another 16.

QAOA.expectation — Function
expectation(ws, sched) -> Float64
expectation(prob, sched; kwargs...) -> Float64

Returns the expectation value of the cost function after the QAOA with the angles sched, i.e. the average cost function of the measured bitstrings.

Input

  • ws::Workspace: The workspace of the problem. Given a problem prob instead, a Workspace is built first, with the keywords kwargs.
  • sched::Schedule: The angles.

Notes

This function computes

\[\langle \hat C \rangle = \langle \beta, \gamma | \hat C | \beta, \gamma \rangle = \sum_x C(x) \, |\langle x | \beta, \gamma \rangle|^2,\]

where $|\beta, \gamma\rangle$ is the final state of the QAOA and the sum runs over all bitstrings $x$.

Mixers and Initial States

QAOA.XMixer — Type
XMixer()

The standard mixer of the QAOA. In a layer with angle $\beta$, it turns every qubit $i$ by $e^{-i\beta \Delta_i X_i}$, where $\Delta_i$ is the mixer factor of an IsingProblem (1 by default).

source
QAOA.XYMixer — Type
XYMixer(pairs)

A mixer that keeps the number of ones in every bitstring. In a layer with angle $\beta$, it applies $e^{-i\beta (X_i X_j + Y_i Y_j)/2}$ to each pair (i, j) in pairs, in the given order. On two qubits, this operator moves amplitude between $|01\rangle$ and $|10\rangle$ and leaves $|00\rangle$ and $|11\rangle$ alone.

Notes

Use it for problems with the constraint that exactly $k$ variables are 1, starting from dicke_state(n, k): every bitstring the QAOA reaches then satisfies the constraint. Pairs along a ring, [(1, 2), (2, 3), …, (n, 1)], or between all variables are common choices.
