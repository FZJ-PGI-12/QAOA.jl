Schedules and Annealing

A Schedule holds the angles $\beta_k$ and $\gamma_k$ of the $p$ layers of the QAOA. On this page, we show three ways to choose them: annealing, a schedule of your own, and optimization. As in the MaxCut example, we take the Petersen graph, whose largest cut has 12 edges:

using QAOA
petersen_edges = [(1, 2), (1, 5), (1, 6), (2, 3), (2, 7), (3, 4), (3, 8), (4, 5), (4, 9),
                  (5, 10), (6, 8), (6, 9), (7, 9), (7, 10), (8, 10)]
max_cut_problem = max_cut(10, petersen_edges)
ws = Workspace(max_cut_problem)
spins(b) = [2 * ((b >> (i - 1)) & 1) - 1 for i in 1:10]
largest = [objective(max_cut_problem, spins(b)) == 12 for b in 0:2^10-1]
probability_of_largest_cut(schedule) = sum(probabilities(ws, schedule)[largest])

Annealing

A quantum annealing turns the mixer slowly into the cost function. Cut into $p$ steps of length $\tau$, it is a QAOA with the angles

\[\begin{align*} \gamma_k = \tau \frac{k}{p}, \qquad \beta_k = \tau \Big(1 - \frac{k - 1}{p}\Big). \end{align*}\]

For this most basic case of a linear annealing schedule, all we need is linear_schedule(p, τ). The total annealing time is $p\tau$. Note that $\gamma$ is measured in units of the fieldscale of the problem, so the same $\tau$ suits many problems; values between 0.5 and 0.7 usually work well. Longer annealing finds the largest cut more often:

[probability_of_largest_cut(linear_schedule(p)) for p in (10, 20, 40, 80)]
4-element Vector{Float64}:
 0.549137690374739
 0.8290528891064248
 0.9978558517009504
 0.9964480524210972

A Schedule of Your Own

Any two vectors of angles make a schedule. Given an annealing path $s(t)$ from 0 to 1, we can set $\gamma_k = \tau s(t_k)$ and $\beta_k = \tau (1 - s(t_k))$. For example, the path $s(t) = \sin^2(\pi t/2)$ starts and ends slowly:

function sine_schedule(p, τ = 0.5)
    s = [sin(π * k / 2p)^2 for k in 1:p]
    Schedule(τ .* (1 .- s), τ .* s)
end
[probability_of_largest_cut(sine_schedule(p)) for p in (10, 20, 40, 80)]
4-element Vector{Float64}:
 0.3671486896087278
 0.7500510246458298
 0.9636401674432852
 0.9983625602210713

For this problem, the linear path is better with few layers.

Optimization

optimize_schedule tunes the angles with the BFGS method, using exact gradients. Started from a schedule, it finds a nearby optimum:

tuned, value = optimize_schedule(ws, linear_schedule(3))
value
11.723643298153776

Alternatively, we can pass the number of layers. optimize_schedule then builds the schedule layer by layer: it optimizes one layer, and then starts each further layer from the interpolate_schedule of the previous optimum. Since good angles change smoothly with the number of layers, each search starts close to its optimum.

tuned, value = optimize_schedule(ws, 4)
probability_of_largest_cut(tuned)
0.9767461674047987

Other Optimizers

expectation_and_gradient! returns the expectation value and writes its derivatives with respect to $\beta$ and $\gamma$ into two vectors. A gradient-based optimizer needs nothing more. With Optim.jl, for example, we can write:

using Optim

# the negative average cut and its gradient: Optim minimizes, but we maximize the cut
function negative_cut!(F, G, angles)
    p = length(angles) ÷ 2
    schedule = Schedule(angles[1:p], angles[p+1:end])
    if G === nothing
        value = expectation(ws, schedule)
    else
        value = expectation_and_gradient!(view(G, 1:p), view(G, p+1:2p), ws, schedule)
        G .*= -1
    end
    F === nothing ? nothing : -value
end

start = linear_schedule(4)
result = optimize(Optim.NLSolversBase.only_fg!(negative_cut!), vcat(start.β, start.γ), LBFGS())
-Optim.minimum(result)      # 11.9365…, the value optimize_schedule finds from the same start
